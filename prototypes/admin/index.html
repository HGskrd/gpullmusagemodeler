The problem with today’s /admin

From reading prod (495 snapshots, 10 visitors per page):
  • It’s an event log, not a view of people. Every visitor card has the same shape and nothing says who they are, where they’re from or why they came.
  • Most rows are noise. The default scenario’s open snapshot repeats in full on nearly every visit.
  • The main journey is invisible. Prod shows open → session_reset → gpu_add and then nothing. /model/add, /model/remove, /model/prec and /gpu/qty don’t record a snapshot (web/planner.py, untracked _htmx_response), so the models people try are never seen.
  • You are in the data. a45934d3 (50 events, multi-tab) is almost certainly you and skews every count.
  • Agent API traffic doesn’t appear at all.

 Proposal 3

People

Replaces the stream: a searchable directory (one row per person) and a profile that reads each visit as a story, with inferred intent and their final plan.

  • What was this person trying to do?
  • Did they get an answer?
 Proposal 4

Journeys & friction

Funnel from landing to “took a plan away”, by persona/device/channel/country. What people do after “doesn’t fit”, common paths, friction signals with example people.

  • Where do people get stuck?
  • Which fixes would help most?
 Proposal 5

Demand & gaps

Model-size × hardware heatmap, top GPUs/models with fit rates, “wanted but didn’t fit” with the smallest fix, zero-result searches, precision habits, agent questions, $/hr entered.

  • What should go into the catalog next?
  • Which presets would answer people fastest?

Instrumentation these pages need

In rough order of value per effort. None store IPs or need a consent banner beyond what a first-party cookie already needs.
  1. Track the untracked planner routes. Switch model_add / model_add_many / model_remove / model_prec / model_count / gpu_qty / gpu_cost in web/planner.py to _tracked_htmx_response. Without this, proposals 3–5 have no model data.
  2. Visitor table with first-touch context. On first request for a new planner_vid, store CF-IPCountry, cf-ipcity/cf-region/cf-timezone (Cloudflare managed transform), Referer host, utm_*, entry path, UA class (desktop/mobile/agent + named bot), and the first Accept-Language tag. Powers proposal 1 and persona context.
  3. Store a slim event, not the full A/B state, per action. Add an events table (visitor, session, t, type, small JSON detail) next to snapshots. Keep full snapshots for “open” and the session’s last state. Makes funnels and paths cheap, and drops the repeated default-scenario rows.
  4. Record the fit outcome server-side after each recompute: fits?, need GB, have GB. This is the main friction signal.
  5. Log zero-result picker searches from /picker/gpu and /picker/model. The most direct catalog-gap signal.
  6. Mark internal traffic. Set a flag on the visitor when the admin session cookie is present. Removes you from every chart.
  7. Log agent API calls (web/agent_api.py) with UA and the request’s model/GPU. Shows what assistants tell people about running models.
  8. Client beacons for copy-link / export / scroll depth (one small POST). The “took it away” stage of the funnel.
